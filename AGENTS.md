# AGENTS.md: notes for coding agents

Read README.md first. This repository is open hardware: 3D-printed motor drives for cam-driven story boxes, their shared ESP32-C6 firmware and web app, and the documentation to build them.

There is one folder per drive version under `drives/` (`mg90s`, `n20`). Each has the same layout, `cad/` beside `docs/`, so scripts and relative links behave the same in every drive. Anything used by more than one drive (firmware, fasteners, classroom material) stays at the top level.

## Where things are

| Path | What | Notes |
|---|---|---|
| `firmware/` | ESP-IDF firmware + Vite web app | Has its own `AGENTS.md`; read it before touching firmware. Apache-2.0. |
| `drives/<drive>/cad/step/` | `.step` and `.f3d` exports of the Fusion design | The live design is in the owner's Fusion account; these are snapshots. Re-export after design changes. |
| `drives/<drive>/cad/stl/` | Print-ready STLs + `README.md` | Generated by that drive's `cad/fusion/orient_stl.py` from its `cad/stl/raw/` exports; the parts table in the README is rewritten between `<!-- parts -->` markers. |
| `drives/<drive>/cad/fusion/` | Fusion scripts | `wires.py` rebuilds the `Wiring` component from waypoint lists; the mg90s drive's `photo.py`/`steps.py` render its `docs/images`, and the n20 drive's `shots.py` reuses `photo.py` for its own (set `CAM_REPO` to the checkout; `shots.py` sets `CAM_DRIVE` itself). Run inside Fusion (or via the Fusion MCP server with `exec(open(...).read())`). |
| `drives/<drive>/docs/` | parts, wiring, cut list, assembly | Markdown + CSV. Wire IDs (MG90S: W1–W11, L1–L3, J1–J2, R1; N20: W1, W2, W4–W15, L1, L2, W6p–W11p on the pod side of connector J3, J1, J2, C2, and D1's own leads) must match `cad/fusion/wires.py` body names and `docs/cut-list.csv`. Cut lengths: routed polyline length × 1.15 + 10 mm, rounded up to 5 mm. |
| `drives/<drive>/docs/images/schematic.svg` | the circuit | Hand-drawn SVG, not an EDA file. Keep it in step with the connections table in `docs/wiring.md`; bump the REV in its title block when it changes. |
| `hardware/` | fastener table + McMaster STEP files | |
| `classroom/` | teaching notes + example stories | Story JSON must match the firmware's format (see `firmware/README.md`). |

## Conventions

- Documentation is Markdown, data is CSV or JSON. No Word, Excel or PowerPoint files.
- Units: millimetres in CAD and scripts; inches only where a part is sold in inches (dowels, wood screws), with mm alongside.
- Images in `docs/images/` are rendered from the model; when the model changes, re-render rather than editing images, and keep alt text accurate to what the image shows.
- Keep every part's swept radius around the servo axis under 13.5 mm: the mount's side walls are 14.75 mm from the axis. The one exception is the N20 drive's 5/8 clamp with its M3 cap screws (14.3 mm at z 16.7–22.2), which runs inside the 0.6 mm wall relief (15.3 mm); recheck it with a swept-cylinder intersection if the clamp or the relief changes.
- The pod's interior is 23 × 34 × 22 mm; check clearances (Fusion interference or boolean intersection) after moving anything inside it.
- In Fusion, moving occurrences in a parametric design needs `design.snapshots.add()` afterwards, or a later parameter change resets their positions.

## Versions

- Tag a drive's releases `vMAJOR.MINOR-<drive>` (e.g. `v1.0-mg90s`), and note in that drive's `cad/README.md` which Fusion document and version the tag matches.
- Each drive has its own Fusion document in MovementStudy › Cam Rotation Tool. Don't change one drive's document to suit another; copy the change across deliberately.
- A fix to a part two drives share (bushings, gauges, shims) belongs in both drives' Fusion documents and STL sets until shared parts get their own folder.
